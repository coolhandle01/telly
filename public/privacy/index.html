Privacy policy

telly · last updated 17 September 2026

telly builds a day’s television schedule out of your YouTube subscriptions and plays the programmes in YouTube’s embedded player. This policy describes the version of telly served at telly.na-n.xyz, built from the repository linked at the foot of this page.

How telly is put together

telly is a single page that runs in your browser. It has no server of its own, no database of its own and no user account. The requests it makes go to accounts.google.com for sign-in and to www.googleapis.com for the YouTube Data API. The page carries a Content Security Policy that allows connections to those two hosts and to the site’s own origin, script from the site’s own origin, accounts.google.com and www.youtube.com, and frames from www.youtube.com, www.youtube-nocookie.com and accounts.google.com.

No code in the page sends anything read from your account to the developer or to any host other than the ones named above.

What telly asks for

One OAuth scope:

https://www.googleapis.com/auth/youtube.readonly

It is read-only. It lets telly read the channels you subscribe to and the uploads on those channels. It carries no permission to post, comment, subscribe, unsubscribe or delete.

What telly reads from YouTube

  • Your account’s own channel id, from a channels.list call with mine=true. It is what the cached schedule data is filed under.
  • Your subscription list: the id and title of each channel you subscribe to.
  • Each of those channels: its uploads playlist, the topic categories YouTube assigns it, and its subscriber count where the channel publishes one.
  • Recent uploads on each channel, twenty per channel: video id, channel id, title, duration, publication date, category, the uploader’s tags, view count, YouTube’s age-restriction flag, whether the video is declared as made for children, whether it may be embedded, and whether it is live.

Those fields decide which of five stations a channel belongs to and what time of day its programmes go out. telly requests no profile scope and asks for no name, email address or watch history.

What is kept on your device

  • The access token. Google Identity Services issues one and issues no refresh token with it. It is held in memory in the page for about an hour. It is not written to storage, not put in a URL or a query string, and not copied into log output or error messages. Closing the tab ends it. When it expires, telly asks Google for another one without showing a screen.
  • A sign-in flag. localStorage, key telly.google.granted, value 1. It records that a consent screen was completed in this browser, which is what lets a later page load take up the grant without prompting you again. It is not the token and it is not a credential. It is removed when you sign out, and when Google refuses to issue a new token.
  • The schedule data. IndexedDB database testcard, object store pools, under the key pool: followed by your account’s own channel id. The record holds the video list and the channel list described above, together with the time it was saved. It exists so that switching the set on again does not spend your API quota. A record more than 24 hours old is not used: the next load fetches from YouTube again and overwrites it.

The key contains your account’s own channel id, so that identifier is in the database as well as in the record. Keying it that way means two accounts used in the same browser do not read each other’s record.

Signing out

The sign-out control in the corner of the page does two things:

  • It calls google.accounts.oauth2.revoke with the current access token. That hands the grant back to Google and drops every scope you granted telly.
  • It removes your record from the pools object store: the one filed under your own channel id. A record belonging to another account that has signed in at this browser is left alone, because it is theirs and not yours to discard. Clearing this site’s data in your browser removes every record.

It also removes the sign-in flag. If the browser refuses to empty the database, or cannot work out which record is yours, the page says so, and the record stays there until a later sign-in overwrites it or you clear this site’s data.

Withdrawing access at Google

You can withdraw telly’s access from Google’s own security settings:

https://security.google.com/settings/security/permissions

The token stops being accepted and no new one is issued, so telly’s next request for one fails and the page returns to its signed-out state. Withdrawing access at Google does not empty the database on your machine. Signing out in the page does that, and so does clearing this site’s data in your browser.

While you are signed out

The schedule is built from a list of sample programmes contained in the page. No request is made to the YouTube Data API and nothing is read from any account. Where a client id is configured for the deployment, the page still fetches Google’s Identity Services script from accounts.google.com when it loads, and Google receives that request. A token is asked for at page load only when the sign-in flag is present in this browser.

In transit

The site and the requests telly makes are HTTPS, and a plain http:// address is redirected to the HTTPS one. HSTS is not set on this site, so a request typed or linked as http:// leaves your browser before it is redirected. The access token travels in an Authorization header rather than in a URL, a query string or a referrer.

How the code is checked

The source is public and every change to it is public. Tests in the repository assert that the access token does not reach localStorage, sessionStorage, a cookie, a request URL or an error object, and a change that breaks one of them fails the checks that run on every pull request. CodeQL runs over the source on pull requests, on pushes to the main branch, and once a week. Dependabot checks the dependencies once a week.

What telly does not do

  • It loads no analytics script, no tracking pixel and no advertising, and it sets no cookie of its own.
  • It has no code that sells, shares or transfers your data to a third party.
  • It builds no profile of you, and it passes what it reads to no service other than the ones named in this policy.

Where the site is served from

telly is a static site. GitHub Pages serves the page, its script and its stylesheet at telly.na-n.xyz. Like any web server, GitHub receives each request, and its documentation says the visitor’s IP address is logged and stored for security purposes. What GitHub does with that is covered by the GitHub Privacy Statement, not by this one.

Sign-in goes from your browser to accounts.google.com, and every YouTube Data API request goes from your browser to www.googleapis.com. Neither passes through the host that serves the page.

YouTube’s player

Programmes play in YouTube’s own embedded player, loaded from www.youtube.com. That player is YouTube’s, not telly’s: it may set cookies and collect data about what you watch, as it would on YouTube. telly cannot see or control what it does.

By using telly you are also using YouTube, so the YouTube Terms of Service and the Google Privacy Policy apply to that part of it.

Limited use

telly’s use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Children

telly is not directed at children and requires a Google account to sign in to. telly requests no profile information and reads no name, email address or date of birth, so it has no way to tell whose account is signed in beyond the channel id described above.

Changes

If this policy changes, the date at the top changes with it, and the history of every version is public in the repository linked below.
